# FabricX Core：为复杂创意应用而生的“架构师”

在当今的 Web 生态中，构建一个功能强大、性能卓越的在线创意编辑器（如设计工具、流程图应用或交互式白板）是一项极其复杂的工程挑战。开发者不仅要应对复杂的图形渲染和状态管理，更要面对不断增长的功能需求所带来的“架构熵增”问题。

**FabricX Core** 正是为此而生。

它**不是**一个 UI 组件库，也**不是**一个大而全的图形引擎。它是一个**面向复杂、创造性 Web 应用的应用框架 (Application Framework)**。它的核心使命是为我们提供一套经过实战检验的**架构蓝图和核心工具集**，让我们从项目第一天起，就能以**可扩展、可维护**的方式构建下一个伟大的应用。

## 为什么选择 FabricX Core？

我们构建 **FabricX Core**，是为了解决在开发大型编辑器应用时反复遇到的三大核心痛点：

1. **架构的无序生长**：随着图层、滤镜、对齐工具、动画等功能的不断叠加，代码库极易变得混乱不堪，模块间依赖错综复杂，最终导致开发效率断崖式下跌，Bug 层出不穷。
2. **核心逻辑与 UI 的紧密耦合**：传统的开发模式常常将业务逻辑、状态管理和 UI 渲染代码混杂在一起，使得更换 UI 框架或进行单元测试变得异常困难且成本高昂。
3. **缺乏统一的“语言”**：不同的功能模块可能由不同的开发者采用不同的模式实现，导致整个项目缺乏一致性，增加了新成员的学习成本和项目的维护成本。

**FabricX Core** 通过提供一套**约定优于配置 (Convention over Configuration)** 的架构范式，旨在从根本上解决这些问题。它为我们提供了坚实的“脚手架”，让我们得以专注于**业务逻辑和创新**，而非一遍又一遍地重复造轮子。

## 核心特性与设计理念

**FabricX Core** 的强大能力源于其几个核心的设计理念，它们协同工作，共同构成了框架的骨架。

* **依赖注入 (DI)**：作为框架的基石，DI 系统彻底解耦了所有模块。这使得每个部分（服务、管理器、命令）都可以被独立开发和测试，确保了高度的模块化。
* **插件化架构**：框架的灵魂所在。几乎所有功能，包括核心功能，都可以被实现为插件。这种设计使得系统具有极致的扩展性，团队可以并行开发不同的功能插件，而不会相互干扰。
* **类型安全的命令系统**：用户的每一个意图都被建模为一个 `Command`。这不仅统一了业务逻辑的入口，还免费提供了**撤销/重做 (Undo/Redo)** 的能力，并通过中间件支持事务历史、日志记录等高级功能。
* **分层架构**：从底层的基础设施到顶层的应用引导，清晰的层次划分确保了职责的单一和系统的稳定。

## 核心价值与适用场景

**FabricX Core** 并非适用于所有项目。它在以下场景中能发挥出最大价值：

* **在线图形/创意编辑器**：这是它的核心领域，例如在线白板、流程图工具、图片编辑器、海报设计工具等。
* **高度可扩展的应用平台**：当你需要构建一个平台，允许第三方开发者或团队内部通过**插件**来扩展核心功能时。
* **需要精细化状态管理的应用**：应用中包含大量复杂、相互关联的状态，且需要支持**撤销/重做 (Undo/Redo)** 等高级功能。
* **对长期可维护性有高要求的项目**：适用于生命周期长、需要多人协作、且未来功能会持续迭代的大型项目。

推荐使用 **FabricX Core** 构建以下类型的应用：

* **在线图形/矢量设计工具**：类似于 Canva 或 Figma。
* **图表与流程图编辑器**：类似于 Miro、Excalidraw、draw.io。
* **在线图片/照片编辑器**：添加滤镜、文本、贴纸等功能。
* **交互式白板与协作工具**。
* **产品定制器**：例如 T 恤、手机壳的在线设计工具。
* 任何需要在画布上进行复杂对象操作和状态管理的 Web 应用。

## 卓越的开发者体验 (Developer Experience)

我们坚信，卓越的开发者体验是构建优秀应用的基石。**FabricX Core** 在设计上处处体现了对开发者的关怀：

* **清晰的边界**：框架通过**依赖注入**和**插件化**强制实现了关注点分离。你编写的业务逻辑（在命令和管理器中）与 UI 框架完全解耦。
* **类型安全**：从始至终的 TypeScript 强类型支持。`ApplicationContext` 和 `inject()` 提供的 API 都是类型安全的，能在编码阶段就发现大量潜在错误。
* **直观的 API**：无论是 `appContext.exec('command')` 的命令执行，还是 `definePlugin(...)` 的插件定义，API 的设计都力求简洁和符合直觉。
* **完善的错误处理与日志**：内置结构化的错误和日志系统，让你在调试和线上监控时不再“盲人摸象”。

## 性能考量

性能是编辑器类应用不可忽视的生命线。**FabricX Core** 的设计在多个层面考虑了性能优化：

* **轻量级核心**：核心模块均为零外部依赖的纯 TypeScript 实现，体积小，执行效率高。
* **按需加载**：插件化的架构天然支持代码分割和按需加载。我们可以只在需要时才加载和激活重量级的功能插件。
* **批量更新**：框架的 `Renderer` 提供了 `batchUpdate` 机制，能将多次 DOM/Canvas 操作合并为一次渲染，有效避免不必要的重绘，保证交互的流畅性。
* **优化的事件与命令系统**：内置了对 `throttle` (节流) 和 `debounce` (防抖) 的支持，可以轻松优化高频触发的命令（如拖拽、缩放）。

## 强大的可扩展性

可扩展性是 **FabricX Core** 的灵魂。

* **万物皆插件**：框架本身就是由一系列核心插件组成的。你可以像我们一样，将应用的每一个功能——无论是对齐线工具、滤镜效果，还是导出为 PDF 的功能——都封装成一个独立的插件。
* **钩子 (Hooks) 系统**：在框架的关键执行点，我们预留了大量的同步/异步钩子。插件可以通过 `tap` 这些钩子，在不修改核心代码的情况下，安全地注入自定义逻辑，改变或增强框架的行为。
* **中间件 (Middleware)**：命令系统和事件系统都支持中间件。你可以编写中间件来实现日志记录、性能监控、权限验证、数据上报等横切关注点，且与核心业务逻辑完全分离。

## 与 UI 框架的集成

**FabricX Core 在设计上是 UI 无关 (UI Agnostic) 的。**

它的核心职责是管理应用的状态、逻辑和数据流。它不关心你使用 React、Vue、Svelte 还是 Angular 来渲染用户界面。

* **清晰的边界**：你的 UI 组件是“消费者”。它们通过 `ApplicationContext` 实例来**调用命令 (`exec`)** 和**订阅事件 (`dispatch` & 监听)**。
* **单向数据流**：UI 组件通过执行命令来**写入**状态，通过监听事件来**读取**状态变更并更新视图。这种清晰的单向数据流使得应用状态变得可预测。
* **解耦**：这种设计意味着，如果你决定从 Vue 迁移到 React，你的所有核心业务逻辑（插件、命令、管理器）都**无需任何改动**。你需要重写的仅仅是 UI 组件层。
